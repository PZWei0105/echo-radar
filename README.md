# 回波 ECHO：選題雷達

痞子葳（PZ）遊戲頻道的選題雷達。每小時掃描一次 Steam、PTT、台灣 Google 新聞與搜尋趨勢、Wikipedia、Reddit，以及《玩真的》整理好的新聞，回答三個問題：**拍不拍、怎麼切、什麼時候發**。

- **回波**：雷達圖。離中心越近越急（中心是今天），顏色越熱分數越高，扇區是頻道路線（檔期推薦、產業爭議、期待榜單、硬體科技、新作焦點）。下面是本週 TOP 5。
- **題庫**：全部題目，可以依路線、截止日、新上榜、需求篩選與排序。
- **預報**：未來 60 天的檔期、值得注意的發售日，以及每個題目的最晚開工日。
- **企劃**：想拍、製作中、已上片。上片後回填 7 天觀看數，雷達會依各路線的成績調整契合度。
- **方向**：四項分數權重、台灣觀眾比重、製作天數、路線偏好、關注清單、靜音、遙控鑰匙。

每個題目都有：四項分數（需求、時效、契合、好做）與理由、各測站讀數、保鮮期、角度三選一（穩／反差／只有你）、附來源的事實清單、PTT 與 Reddit 討論、時間線。按「產生企劃包」會寫出可以直接貼給筆電 Claude Code 的製作指令；按「找 Claude 討論」會把題目資料複製好、打開 Claude。

## 評分

- 總分＝四項加權平均 × 需求係數（0.6＋0.4×需求/100）。需求是乘數：沒人看的題目，再準時、再好做也沒用。
- 預設權重：需求 40、時效 25、契合 20、好做 15；台灣觀眾比重 45%；製作天數 3 天。都可以在 App 的「方向」頁調整，改了馬上重排。
- 等級：70 以上必拍、58 以上可拍、46 以上觀望，其餘先跳過。
- 所有規則都寫在 `config/` 和 `pipeline/`，同樣的資料永遠得到同樣的分數。

## 更新

- GitHub Actions 每小時第 47 分自動跑（`.github/workflows/echo.yml`）。
- App 的「掃描」按鈕：沒有遙控鑰匙時重新讀最新資料；有遙控鑰匙（只能控制這個 repo 的 fine-grained token，Actions 與 Contents 讀寫）時會直接叫 GitHub 重抓一輪，約 3 分鐘。
- 方向設定存在手機；有遙控鑰匙時會同步到 `user` 分支的 `prefs.json`，筆電與手機共用。

## 不需要金鑰、不花錢

全部用公開資料：Steam 商店、統計與評論的公開端點、Wikimedia 統計 API、Wikidata、Google 新聞與趨勢 RSS、Reddit RSS、PTT 網頁版鏡像站（PTT 官網會擋 GitHub 的伺服器；連結一律指回 PTT 原文）、《玩真的》的公開資料。YouTube 擁擠度需要 API 金鑰，目前先不做。
